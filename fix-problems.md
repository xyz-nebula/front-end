**Регрессионные тесты:**

## 6. Отдельный план реальной интеграции

Выполнять после отдельного запроса на интеграцию и согласования контрактов.
Не включать эти реализации автоматически в исправления текущего PR.

### 6.1. Сначала согласовать сервисные контракты — I02, I03

**Backend на проверенной версии:** предоставляет auth/TOTP и chat/message CRUD.
Целевых negotiation endpoints нет. Источники:
`app/api/v1/routers/chat.py`, `models.py`, `auth.py`.

Потребуются:

1. Create/get/list negotiation session с ownership и согласованными case IDs.
2. Атомарный text turn с серверными user/AI messages и идемпотентностью.
3. Короткоживущий одноразовый ticket, привязанный к session и пользователю.
4. Идемпотентный finish и result в состояниях processing/ready/failed.
5. Внутренний авторизованный transcript commit для обеих сторон, дедупликация
   event ID и возврат сохранённого message ID/sequence.
6. Согласованные error DTO, HTTP statuses, срок и область действия idempotency
   keys, поведение при повторе ключа с другим payload.

**Audio-engine на проверенной версии:** читает `token` с `chat_uuid`, принимает
`{ type: 'audio', audio: ... }`, не выдаёт нужные transcript/committed события,
сохраняет только AI transcript; pause/resume не реализованы. Источник:
`web_voice_localai_v1.py`. Документация сервиса сама по себе не доказывает
соответствие реализации.

Потребуются:

1. Ticket handshake вместо несовместимой текущей схемы; безопасная передача
   ticket без логирования полного URL/секрета.
2. Согласованный `audio_input` и PCM `pcm_s16le`, mono, 24 kHz, 16 bit.
3. Partial transcript как полный snapshot, отдельно от committed history.
4. Commit обеих сторон в backend до `message_committed` в браузер.
5. Реальные pause/resume/stop/close и единые errors/close codes/reconnect policy.
6. Явное поведение при завершении сессии во время последней реплики: что
   подтверждено, что ожидается, когда безопасно вызывать finish/result.

**Результат:** согласованные схемы/fixtures для трёх сервисов. Frontend README
не считать односторонним доказательством того, что остальные команды приняли API.
