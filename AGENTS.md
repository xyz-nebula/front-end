# Arena Negotiations — Agent Guide

## Назначение репозитория

«Арена переговоров» — frontend AI-тренажёра переговоров. Репозиторий содержит
интерактивный прототип для desktop и mobile, а также существующие адаптеры к
auth, negotiation backend и audio-engine.

Основной стек: React, Vite, TypeScript и обычный CSS с семантическими scoped-
классами. Новые зависимости добавляются только при обоснованной необходимости.

## Границы изменений

- Поддерживайте существующие auth/negotiation/audio-интеграции и их mock-аналоги.
- Не добавляйте новые backend API, LLM/STT/TTS-возможности, серверное хранение
  или межсервисные протоколы без отдельной задачи.
- Для демонстрационных сценариев используйте локальное состояние и mock-данные,
  если задача прямо не требует реального сервиса.
- Не принимайте значимые продуктовые, дизайн- или архитектурные решения молча.
  Мелкие UI-решения об отступах, адаптивности и состояниях можно принимать
  самостоятельно.

## Инварианты реализации

- Не используйте TypeScript `any`; общие типы выносите только при реальном
  переиспользовании.
- Состояние держите близко к месту использования, повторяющийся UI выносите в
  компоненты, не создавайте абстракции без практической пользы.
- Доступ к auth, negotiation и audio идёт через contracts и mock/real adapters;
  страницы и feature hooks не обращаются к wire API напрямую.
- Локальные данные подготовки и сессий изолируются по владельцу. Не заменяйте
  owner-scoped storage глобальными ключами.
- Маршруты остаются lazy-loaded. Новые экраны подключайте тем же способом.
- Модальные окна сохраняют focus trap, закрытие по Escape, блокировку фона и
  возврат фокуса вызывающему элементу.
- Соблюдайте [styling policy](docs/styling.md) и
  [ADR 0001](docs/decisions/0001-plain-css-foundation.md): foundation —
  `src/styles/global.css`, компоненты используют scoped-классы, landing сохраняет
  namespace `arena-*` и изоляцию от остальных экранов.
- Landing задаёт направление будущей визуальной миграции. Редизайн остальных
  экранов требует отдельной задачи.

## Проверка

- Базовая полная проверка: `npm run check`.
- После UI, CSS или адаптивных изменений: `npm run visual:smoke`, затем вручную
  открыть относящиеся к задаче desktop/mobile PNG из `artifacts/visual-smoke/`.
- При добавлении экрана или важного интерактивного состояния расширяйте
  `tests/visual/`. Скриншоты являются диагностическими артефактами и не
  коммитятся.
