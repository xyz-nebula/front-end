# Styling policy

Основной подход — обычный CSS с семантическими классами, ограниченными
компонентом или экраном. Новые компоненты оформляются scoped CSS-классами;
CSS Modules и дополнительные styling-библиотеки не вводятся.

## Визуальное направление

Landing — утверждённое направление будущей визуальной миграции продукта.
Текущие auth, home, session и dialog-экраны сохраняют существующий дизайн.
Это решение не является разрешением на их редизайн: миграция требует отдельной
задачи с явным объёмом изменений.

## Владение стилями

- `src/styles/global.css` — точка входа общих и продуктовых стилей:
  foundation/shared, auth/session, home, dialogs/404.
- `src/styles/landing.css` — точка входа landing: foundation, header,
  hero/scene, problem, how-it-works, AI-opponent, teams.
- Сохраняйте namespace `arena-*` для landing, его локальные переменные и
  изоляцию от auth/home. Правка landing не должна незаметно менять продуктовые
  `.app-*`, `.auth-*`, `.session-*` или modal-классы.
- Shared-правила содержат только действительно общие примитивы. Responsive
  и reduced-motion правила располагаются у владельца; одинаковые breakpoint
  блоки объединяются лишь с сохранением порядка применимых деклараций.
- Сохраняйте специфичность, порядок импортов и локальные переопределения.
  Порядок breakpoint-блоков тоже часть каскада: более узкий блок не всегда
  можно переместить после более широкого без проверки.

## CSS foundation

Проект использует собственный минимальный reset в `src/styles/global.css` и
обычный CSS с семантическими scoped-классами. Tailwind, его preflight и Vite
plugin, а также MUI, Emotion, `ThemeProvider` и `CssBaseline` не входят в
текущий styling foundation.

Не добавляйте utility CSS, CSS-in-JS или UI-библиотеку попутно с экранной
задачей. Возврат Tailwind/MUI либо выбор другой styling-системы требует
отдельного архитектурного решения и полной visual-проверки существующих экранов.
Причины текущего решения зафиксированы в
[ADR 0001](decisions/0001-plain-css-foundation.md).

## Проверка изменений

После UI/CSS/адаптивных правок запускайте `npm run visual:smoke` и открывайте
относящиеся к изменению PNG через `view_image`. Один зелёный Playwright-прогон
не заменяет визуальную оценку desktop/mobile.

Механическое разделение файлов не меняет DOM, классы, значения свойств и внешний
вид. Для него сохраняйте before PNG и SHA-256 manifest вне репозитория,
повторяйте тот же прогон и сравнивайте одноимённые кадры. Несовпадения нужно
разобрать, а диагностические `artifacts/` и baseline не коммитить.
